age# 3번 담당자: AI Agent와 알림

## 이 파일의 목적

백엔드가 전달한 원본 메시지, 모델 결과, 위험도를 받아서 위험 구간과 사건을 분석하고 관리자가 빠르게 확인할 수 있는 알림을 만드는 부분을 맡는다.

Agent는 학교폭력 여부를 확정하지 않는다. “위험 신호가 보인다”, “추가 확인이 필요하다”는 형태로만 작성한다.

## Agent가 판단하는 위험 구간

백엔드가 전달한 원본 메시지와 모델 결과를 보고 위험 대화의 범위를 정한다. 백엔드는 위험도만 계산하고, 아래 판단은 Agent가 담당한다.

### 같은 구간으로 묶는 경우

- [ ] 같은 사람을 향한 발언이다.
- [ ] 같은 주제의 대화가 계속된다.
- [ ] 시간 간격이 짧다.
- [ ] 배제, 조롱, 압박, 협박이 연속된다.
- [ ] 여러 사람이 같은 사람을 함께 압박한다.

### 다른 구간으로 나누는 경우

- [ ] 시간이 많이 떨어져 있다.
- [ ] 주제가 바뀌었다.
- [ ] 대상이 달라졌다.
- [ ] 이전 대화가 끝난 뒤 새로운 흐름이 시작되었다.

### Agent가 반환할 위험 구간

```json
{
  "risk_chat_segments": [
    {
      "segment_id": "seg_001",
      "start_message_id": "msg_001",
      "end_message_id": "msg_005",
      "evidence_message_ids": ["msg_001", "msg_004"],
      "reason": "특정 사용자를 향해 반복적으로 나가라고 압박하는 대화입니다."
    }
  ]
}
```

관련 위험 구간이 여러 개라면 Agent가 하나의 `incident`로 묶는다. 같은 대상·주제·시간 흐름인지 원본 메시지를 근거로 설명한다.

## 최종적으로 만들 것

```text
위험 사건 + 원본 대화
-> 위험 유형 정리
-> 위험 이유 작성
-> 관리자용 요약 작성
-> 추가 확인할 내용 작성
-> 초기 조치 참고사항 작성
-> 표준 알림 JSON 반환
```

## 1단계: 알림 필드 고정

아래 필드 이름을 바꾸지 않는다.

```json
{
  "risk_chat_segments": [],
  "suspected_risk_types": [],
  "context_reason": "",
  "evidence_message_ids": [],
  "manager_summary": "",
  "missing_context": [],
  "recommended_initial_actions": [],
  "disclaimer": "자동 분석된 위험 신호이며 최종 판단이 아닙니다."
}
```

## 2단계: 위험 유형 정리

원문에서 확인되는 내용만 아래 유형으로 정리한다.

- 반복성: 비슷한 공격이나 배제가 여러 번 나옴
- 표적성: 특정 사람을 향함
- 집단성: 여러 사람이 한 사람을 함께 압박함
- 배제성: 나가라고 하거나 대화에 끼지 못하게 함
- 위협성: 해치거나 퍼뜨리겠다는 말이 나옴
- 공개성: 여러 사람이 보는 곳에서 반복됨

### 해야 할 일

- [ ] 해당되는 유형만 넣는다.
- [ ] 원문에 없는 유형을 억지로 넣지 않는다.
- [ ] 유형마다 근거 메시지 ID를 연결한다.

## 3단계: 위험 이유 작성

위험 이유는 다음 순서로 작성한다.

```text
1. 실제로 보이는 표현이나 흐름
2. 그 표현이 이어진 방식
3. 그래서 추가 검토가 필요한 이유
```

좋은 표현:

```text
특정 사용자를 향해 대화에서 나가라고 요구하는 표현이 여러 번 나타났고,
다른 참여자도 같은 대상에게 동조하는 흐름이 보입니다.
이는 배제와 압박의 위험 신호로 볼 수 있어 전후 대화 확인이 필요합니다.
```

피해야 할 표현:

```text
A는 가해자이고 B는 피해자입니다.
이것은 학교폭력 사건입니다.
```

## 4단계: 원본 근거 연결

- [ ] Agent가 참고한 메시지 ID를 `evidence_message_ids`에 넣는다.
- [ ] 모든 ID가 실제 입력에 있는지 확인한다.
- [ ] 원본 문장을 임의로 고치지 않는다.
- [ ] 원본 시간과 메시지 ID를 위험 구간 안에 표시한다.
- [ ] 입력에 없는 의도, 과거 사건, 관계를 만들지 않는다.

## 5단계: 관리자용 요약 작성

관리자용 요약은 2~4문장으로 짧게 쓴다.

포함할 내용:

- 언제 발생했는지
- 어떤 흐름이 반복되었는지
- 어떤 위험 신호가 있는지
- 무엇을 추가로 확인해야 하는지

예시:

```text
14:28~14:30 사이 특정 사용자를 대화에서 배제하고 퇴장을 요구하는 표현이 반복되었습니다.
다른 참여자가 같은 대상에게 동조한 흐름도 확인됩니다.
전후 대화와 당사자 상황을 함께 검토해야 합니다.
```

## 6단계: 누락 맥락 작성

확인할 수 없는 정보는 숨기지 말고 `missing_context`에 넣는다.

예시:

- 대화 이전에 어떤 일이 있었는지 알 수 없음
- 실제 당사자의 의도를 확인하지 못함
- 다른 채널에서 같은 일이 반복되었는지 확인하지 못함
- 농담인지 실제 압박인지 원문만으로 확정하기 어려움

## 7단계: 초기 조치 작성

조치는 처벌이나 확정 판단이 아니라 관리자 확인 순서로 쓴다.

예시:

- 원본 메시지와 앞뒤 대화를 함께 확인한다.
- 관련 메시지를 보존한다.
- 대화에 참여한 사람들의 상황을 별도로 확인한다.
- 피해 가능성이 있는 사람에게 안전한 도움 요청 방법을 안내한다.
- 필요하면 담당 교사, 보호자 또는 운영 담당자에게 검토를 요청한다.

## 8단계: Agent 요청 흐름

처음에는 한 번에 모든 것을 생성해도 되지만, 결과가 불안정하면 두 단계로 나눈다.

```text
분석 단계:
위험 유형, 위험 이유, 근거 ID, 누락 맥락 작성

정리 단계:
분석 결과를 표준 알림 JSON으로 변환
```

### 해야 할 일

- [ ] 입력에는 `analysis_id`, `room_id`, 모델 점수, 위험 단계, 원본 메시지를 넣는다.
- [ ] 입력에 `incident_id`나 위험 구간을 미리 넣지 않는다.
- [ ] 모델 점수만으로 결론을 내리지 않게 한다.
- [ ] 원본 메시지를 근거로 쓰게 한다.
- [ ] 반드시 JSON 형식으로 받는다.
- [ ] JSON이 깨지면 재시도하거나 안전한 기본 응답을 사용한다.

## 9단계: 출력 검증

Agent 결과를 외부 알림으로 보내기 전에 반드시 확인한다.

- [ ] 필수 필드가 모두 있는가
- [ ] `evidence_message_ids`가 실제 입력에 있는가
- [ ] 원본 메시지 내용이 바뀌지 않았는가
- [ ] `disclaimer`가 있는가
- [ ] 확정 판정 표현이 없는가
- [ ] 가해자·피해자를 확정하지 않았는가
- [ ] 입력에 없는 사건이나 의도를 추가하지 않았는가

검증에 실패하면 외부 채널로 보내지 않는다. 화면에는 “알림 검증 실패”를 보여준다.

## 10단계: 알림 전달 담당자와 연결

MCP나 외부 채널은 분석을 하지 않는다. 3번 담당자는 검증이 끝난 표준 알림만 넘긴다.

```text
입력: analysis_id + room_id + room_name + notification_email + incident + messages
출력: channel + status + sent_at + external_message_id + notion_url + recipient_email
```

첫 MVP에서는 실제 외부 전송을 하지 않아도 된다.

```json
{
  "channel": "none",
  "status": "not_configured",
  "sent_at": null,
  "external_message_id": null,
  "recipient_email": "teacher@example.com"
}
```

## 완료 기준

- [ ] 정해진 필드의 표준 알림이 나온다.
- [ ] 위험 이유와 메시지 ID가 연결된다.
- [ ] 원본에 없는 내용을 만들지 않는다.
- [ ] 확정 판정 문구가 없다.
- [ ] 누락 맥락과 초기 조치가 포함된다.
- [ ] 검증 실패 시 외부 전송을 막는다.
- [ ] Agent 실패 시 백엔드가 사용할 기본 응답을 준비한다.
