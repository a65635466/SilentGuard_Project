# Phase 02: 위험 구간 분석

## 목표

위험 메시지 한 줄이 아니라 이어지는 대화를 하나의 구간으로 묶는다.

## 해야 할 일

- [x] Phase 1 입력 계약을 재사용해 Agent 입력을 검증한다.
- [x] 원본 `messages`를 OpenAI API에 전달하는 호출 코드를 작성한다.
- [x] 위험 구간 출력 JSON Schema를 정의한다.
- [x] 위험 구간의 시작·종료·근거 메시지 ID를 입력 원본과 대조한다.
- [x] 로컬 CLI 실행 파일과 mock transport 테스트를 작성한다.
- [ ] `OPENAI_API_KEY`를 넣고 실제 API 응답으로 구간 생성 결과를 확인한다.

## Phase 1에서 이어받은 전제

- 백엔드는 위험 구간을 만들지 않는다.
- Agent는 백엔드가 넘긴 원본 `messages` 안에서만 구간을 만든다.
- 첫 MVP에서 Agent 입력 문맥은 `warning` 이상일 때 최근 10개 메시지를 기본값으로 둔다.
- 입력에 없는 메시지 ID, 시간, 원문은 만들지 않는다.

## 같은 구간 기준

- 같은 사람 또는 같은 관계 흐름을 향함
- 같은 주제의 대화가 이어짐
- 입력된 문맥 안에서 시간 흐름이 끊기지 않음
- 배제·조롱·압박·협박 표현이 이어짐
- 여러 사람이 같은 사람을 함께 압박함

## 다른 구간 기준

- 입력 문맥 안에서도 시간 흐름이 끊겨 보임
- 주제가 바뀜
- 대상이 바뀜
- 이전 흐름이 끝남
- 근거가 부족해서 같은 흐름이라고 보기 어려움

## MVP 구간 판단 방식

첫 MVP에서는 복잡한 시간 기준을 넣지 않는다. Agent는 백엔드가 넘긴 최근 10개 메시지 안에서 대화 흐름을 보고 구간을 만든다.

구간을 만들 때는 아래처럼 판단한다.

- 위험 표현만 따로 떼지 않고 앞뒤 맥락을 포함한다.
- 실제 위험 판단에 쓴 메시지만 `evidence_message_ids`에 넣는다.
- 같은 흐름인지 애매하면 억지로 합치지 않는다.
- 왜 나눴는지 또는 왜 추가 확인이 필요한지는 `reason`이나 `missing_context`에 남긴다.

## 현재 적용할 임시 출력 구조

Agent는 백엔드가 전달한 원본 문맥에서 구간을 선택한다. 백엔드는 이 결과를 만들거나 수정하지 않는다.

```json
{
  "risk_chat_segments": [
    {
      "segment_id": "seg_001",
      "start_message_id": "msg_001",
      "end_message_id": "msg_005",
      "evidence_message_ids": ["msg_001", "msg_004"],
      "start_at": "2026-08-08T14:28:00+09:00",
      "end_at": "2026-08-08T14:30:00+09:00",
      "reason": "특정 사용자를 향해 반복적으로 나가라고 압박하는 대화입니다."
    }
  ]
}
```

구간에는 위험 근거가 되는 메시지뿐 아니라 흐름을 이해하는 데 필요한 주변 원본 메시지도 포함한다. 단, `evidence_message_ids`에는 실제 위험 판단에 사용한 메시지만 넣는다.

## 예시

아래처럼 특정 사용자를 계속 배제하는 흐름이면 하나의 구간으로 묶는다.

```text
msg_001 A: 너 왜 또 여기 들어왔냐
msg_002 B: 그냥 같이 얘기하려고
msg_003 C: 나가
msg_004 A: 아무도 너랑 하기 싫대
```

이 경우 구간은 `msg_001`부터 `msg_004`까지 잡고, 근거는 위험 표현이 있는 `msg_001`, `msg_003`, `msg_004`를 넣는다.

아래처럼 대상이나 주제가 바뀌면 나눈다.

```text
msg_001 A: 너 왜 또 여기 들어왔냐
msg_002 C: 나가
msg_003 D: 숙제 몇 쪽까지야?
msg_004 A: 내일 단톡에서 얘기하자
```

`msg_003` 이후는 같은 위험 흐름으로 묶지 않는다.

## Phase 2 결과

- 위험 구간은 Agent가 원본 문맥 안에서 직접 구성한다.
- 같은 대상, 같은 주제, 이어지는 시간 흐름, 반복되는 위험 표현이면 하나의 구간으로 묶는다.
- 주제, 대상, 흐름이 바뀌거나 근거가 부족하면 구간을 나눈다.
- 구간에는 앞뒤 맥락을 포함하지만, `evidence_message_ids`에는 실제 위험 근거만 넣는다.
- 첫 MVP에서는 별도 시간 분 단위 기준을 두지 않고 최근 10개 메시지 window 안에서 판단한다.

## 남은 문제

- 실제 대화가 길어지면 window 밖 구간을 이어 붙이는 기준이 필요하다.
- 시간 간격 기준은 실제 샘플을 보고 조정한다.

## 완료 조건

반환하는 모든 구간에 시작·종료 ID, 근거 ID, 이유가 있다.
